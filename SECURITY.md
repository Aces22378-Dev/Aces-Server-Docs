# SECURITY POLICY

**Author:** Aces22378-Dev

## 1. PURPOSE

This document explains how security issues affecting the server or its public documentation should be reported.

Security problems should be handled privately so they can be investigated and fixed without unnecessarily exposing the server or its members.

## 2. DO NOT PUBLICLY DISCLOSE ACTIVE VULNERABILITIES

Do not publicly post:

* Exploit instructions.
* Passwords.
* Bot tokens.
* API keys.
* Private database information.
* Personal information.
* Security bypass methods.
* Information that could allow others to abuse an active vulnerability.

## 3. REPORTING SECURITY ISSUES

Security issues should be reported privately to the appropriate Developer, Administrator, Executive, or Server Owner.

A report should include, when possible:

**Issue:**
What appears to be wrong.

**Affected system:**
The feature or system affected.

**Impact:**
What could happen if the issue is abused.

**Evidence:**
Relevant screenshots, logs, or other information.

**Reproduction:**
Safe reproduction information when appropriate.

## 4. RESPONSIBLE DISCLOSURE

After reporting a vulnerability, allow the appropriate staff to investigate and address the issue before publicly discussing technical details.

Do not use the vulnerability against other members or server systems.

## 5. EXPOSED CREDENTIALS

If a password, token, API key, or other secret is accidentally exposed:

1. Do not share it further.
2. Notify the appropriate Developer or Administrator.
3. Treat the credential as compromised.
4. Revoke or replace it as appropriate.
5. Review relevant systems if necessary.

## 6. PRIVACY

Do not include unnecessary personal information in security reports.

Only provide information needed to investigate the issue.

## 7. GOOD-FAITH TESTING

Authorized testing should remain within the scope provided by the server.

Do not intentionally damage systems, access unrelated accounts, or obtain information that is not necessary for the investigation.

## 8. FINAL NOTE

Security reports should help the server identify and fix problems.

When in doubt, report a suspected security issue privately rather than publicly.
